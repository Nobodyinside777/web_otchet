# Техзадание: локальное приложение для «Прогноза выручки»

## 1. Цель

Пользователь регулярно получает Excel-книгу одного и того же формата. Из неё нужен только лист **«Прогноз выручки»**. Пользователю нужно:

1. Загрузить файл в локальное веб-приложение и сразу узнать, соответствует ли он формату.
2. Работать с таблицей в браузере: фильтры, сортировка, группировки, суммы по колонкам, сводные таблицы.
3. Выгрузить результат того, что он настроил на экране:
   - в **Excel** с настоящей сводной таблицей (PivotTable) и живыми формулами;
   - в **PDF** с тем же содержимым.

Приложение пользуется только сам пользователь на своём компьютере. Иногда он передаёт папку с программой коллегам, и у них оно должно запускаться так же просто.

## 2. Ограничения

| Что | Требование | Почему |
|---|---|---|
| Данные | Полностью локально, офлайн, без внешних сервисов и телеметрии | Коммерческая тайна |
| ОС | Windows 10/11 | Так у пользователя и коллег |
| Excel | Microsoft Excel 2019 установлен | Нужен для PivotTable и PDF |
| Размер файла | До 200 МБ (текущий образец около 10 МБ) | Файлы будут расти |
| Интерфейс | Браузер, адрес `http://127.0.0.1:<порт>` | Привычно и без установки клиента |
| Запуск | Двойной клик по `run.bat` | Пользователь и коллеги не программисты |

## 3. Входной файл

### 3.1. Книга

Книга содержит около 14 листов: «Выгрузка 1С», «Мэпинг», «Константы», отчётные листы и другие. Приложение читает **только** лист «Прогноз выручки», остальные игнорирует.

Почти все ячейки листа содержат формулы, ссылающиеся на другие листы. Приложение использует **вычисленные значения**, сохранённые Excel в файле (python-calamine читает именно их). Если значений нет, например файл сохранён не из Excel, нужно показать ошибку: «Откройте файл в Excel, сохраните и загрузите снова». Запасной вариант на будущее: пересчитать книгу через Excel COM перед чтением.

### 3.2. Структура листа

- **Строка 1** служебная. В ней номера колонок, а в ячейке **Z1** порог вероятности (сейчас 0,5), от которого зависит колонка Z.
- **Строка 2** с заголовками.
- **Строки 3 и ниже** с данными. Сейчас около 460 строк, в будущем больше. Пустые строки в конце игнорируются.
- Справа от AA, в колонках AB–AC без заголовков, есть служебный текст. Его игнорируем.
- Лист отформатирован на тысячи пустых колонок, поэтому читаем только до AA.

### 3.3. Особенности данных

- **Колонки идентифицируются по букве (позиции), а не по названию**, потому что «МП, руб.» встречается дважды. Внутри кода давать колонкам уникальные латинские имена (например `revenue`, `cost`, `margin_rub`, `margin_pct`, `cost2`, `margin_rub2`), а в интерфейсе показывать русские названия.
- В числовых колонках встречаются ошибки Excel (`#VALUE!`), пробелы и пустые ячейки. Считать их пустыми (null) и показывать пользователю предупреждение: сколько таких ячеек и в каких строках.
- Маржу % нельзя суммировать. В сводных она пересчитывается как `сумма МП / сумма выручки`.

## 4. Проверка формата

При загрузке файла проверить:

1. Есть лист «Прогноз выручки».
2. В строке 2 в колонках B–AA стоят ожидаемые заголовки. Сравнение после нормализации: убрать пробелы по краям, схлопнуть повторные пробелы и переносы строк.
3. В измерениях и мерах типы данных соответствуют ожидаемым, с допуском на ошибки из п. 3.3.
4. Есть значения формул (п. 3.1).

Если что-то не совпадает, приложение не продолжает работу и показывает понятное сообщение с конкретикой. Например: «Колонка R: ожидался заголовок „МП, руб.", найдено „Маржа"». Список ожидаемых заголовков хранить в одном месте, в конфиге, чтобы его было легко обновить.

## 5. Функции интерфейса

1. **Загрузка файла**: перетаскиванием или выбором. Показать прогресс, для 200 МБ он нужен.
2. **Таблица**: просмотр с прокруткой, сортировка по любой колонке.
3. **Фильтры** по измерениям: множественный выбор значений, диапазоны для дат и чисел.
4. **Итоги**: суммы, количество, среднее, минимум и максимум по выбранным колонкам для отфильтрованных строк.
5. **Конструктор сводной**: пользователь выбирает поля для строк, колонок и значений и функцию агрегации. Результат сразу показывается на экране.
6. **Пресеты**: сохранить текущую настройку (фильтры и сводную) под именем и загрузить позже. Хранить локально в JSON рядом с приложением.
7. **Экспорт в Excel** (п. 6.1) и **экспорт в PDF** (п. 6.2).

Список действий будет расширяться, поэтому архитектура должна позволять добавлять новые операции без переписывания остального.

## 6. Экспорт

### 6.1. Excel

Excel собирается через COM (pywin32) в установленном Excel 2019:

- Лист **«Данные»**: отфильтрованные строки как умная таблица (ListObject) с понятными заголовками.
- Лист **«Сводная»**: настоящая PivotTable на основе таблицы «Данные» с теми же строками, колонками, значениями и фильтрами, что пользователь выбрал на экране. Маржа % считается вычисляемым полем (`МП / Выручка`).
- Строка итогов на листе «Данные» через формулы `SUBTOTAL`, чтобы итоги оставались живыми.
- Имя файла по шаблону `Прогноз_<пресет или дата>_<ГГГГ-ММ-ДД_ЧЧ-ММ>.xlsx`.

Excel запускается невидимым, без диалогов, и всегда закрывается в `finally`.

### 6.2. PDF

PDF делается из того же Excel-файла средствами Excel (`ExportAsFixedFormat`), чтобы выглядел так же, как в Excel:

- альбомная ориентация, «вписать по ширине страницы»;
- шапка с названием пресета, датой формирования и описанием применённых фильтров;
- в PDF идёт лист «Сводная», а лист «Данные» добавляется по флажку в интерфейсе.

## 9. Этапы

Каждый этап заканчивается проверкой у пользователя.

1. **Каркас**: структура проекта, `run.bat`, пустое приложение Streamlit открывается в браузере.
2. **Загрузка и проверка**: `schema.py`, `loader.py`, `validate.py` и тесты на образце, включая проверку, что испорченный файл даёт понятную ошибку.
3. **Таблица, сортировка, фильтры, итоги.**
4. **Конструктор сводной** на экране.
5. **Экспорт в Excel** с PivotTable через COM.
6. **Экспорт в PDF.**
7. **Пресеты.**
8. **Производительность**: проверка на синтетическом файле около 200 МБ, сгенерированном по схеме из образца.
9. **Упаковка для коллег**: папка, которую можно скопировать и запустить через `run.bat`, плюс короткая инструкция `README.txt`.
